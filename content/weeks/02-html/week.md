Last week you wrote your first web page. This week you'll learn to write HTML **well**: HTML that is clear for other developers, friendly for search engines, and usable by everyone, including people who use screen readers or a keyboard instead of a mouse.

We'll start with **semantic HTML**: choosing tags that describe what your content means, like `<header>`, `<nav>`, `<main>` and `<footer>`. Then we'll go deeper into links, images, lists and tables, and how to use each one properly.

Next come **forms**, the way websites collect information: sign-ups, searches, orders and messages. You'll learn the different input types, why every input needs a label, and how the browser can check answers for you.

Finally, you'll learn why **accessibility** matters and how to check your own work using the HTML validator and the DevTools Elements panel. These are habits professional developers use every day.

## By the end of this week you will be able to

- Structure a page with semantic elements and a sensible heading order
- Use links, images (with good alt text), lists and tables correctly
- Build a form with labelled inputs, buttons and validation attributes
- Explain why accessibility matters and apply some basic accessibility checks
- Use the HTML validator and DevTools to find and fix mistakes
